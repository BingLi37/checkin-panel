# Check-in runs over the site's HTTP API, not a browser

Every target is a New API / One API fork, so the check-in is done with plain HTTP against the public surface (`GET /api/status`, `POST /api/user/login`, `GET /api/user/self`, and the fork's check-in route if it has one) — see `panel/newapi.py`. This was chosen over the inherited approach of driving the SPA in a headless browser because a check-in is three requests and about a second, while a browser launch is hundreds of MB and tens of seconds per account, and every UI change upstream broke the automation. The cost is that each fork's quirks must be discovered rather than clicked: `panel/newapi.probe` reads `/api/status` for login methods and `quota_per_unit`, then POSTs the known check-in paths unauthenticated to find which one exists.

**Consequences**:
- Route detection must be **POST-only and unauthenticated**. `GET /api/user/checkin` matches the admin route `/api/user/:id` and answers 200, which mistakes every bonus-on-login site for one with a check-in endpoint; an *authenticated* POST would perform the check-in and steal the before-balance from the real run.
- A `session` cookie's presence proves nothing — New API stores the pre-login OAuth state in one. Only `GET /api/user/self` (`newapi.whoami`) proves a login.
- Turnstile-protected forks are not out of reach after all, but they cost a browser. `seekai.cc` answers `POST /api/user/checkin` with `Turnstile token 为空`, and its SPA never renders the widget in cloakbrowser — so `browser_login(turnstile_key=…)` renders it *itself* (`turnstile.render`, the API is already loaded by the page) and the check-in POST carries the token as a query param, exactly where the site's own SPA puts it: `?turnstile=…` → `{"message":"签到成功","quota_awarded":10000000}`. Clicking the site's 签到 button was tried first and is **not** equivalent: the click succeeds while the request behind it is refused, which reported a check-in that never happened.
- Route detection must also require a JSON content-type: a WAF that answers 200 HTML to every path would otherwise make every site look like it has a check-in route (ADR-0010).
